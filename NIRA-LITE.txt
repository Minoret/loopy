### Network InteRvention Analysis - Implementación Client-Side para Redes Psicopatológicas Dinámicas

---

## 1. 🎯 Visión General del Sistema

### 1.1 ¿Qué es NIRA?

**NIRA** (Network InteRvention Analysis) es un algoritmo de identificación de dianas de intervención en redes de psicopatología. La versión académica original fue propuesta por **Lunansky et al. (2022)** en *Methods* y se basa en el modelo de Ising para datos binarios.

**Nuestra implementación en Loopy** difiere fundamentalmente del NIRA académico en tres aspectos:

| Característica | NIRA Académico (Lunansky 2022) | NIRA-Loopy (nuestra versión) |
|---|---|---|
| **Modelo subyacente** | Ising Model (binario, estático) | Sistema dinámico continuo (Loopy nativo) |
| **Tipo de datos** | Cross-sectional binarizado | Tiempo real, valores continuos [0,1] |
| **Métrica de impacto** | Diferencia de sum-scores post vs. pre | AUC (Área Bajo la Curva) temporal |
| **Intervención simulada** | Alteración del threshold (intercept) | Clamping del nodo a valor 0 |
| **Ejecución** | R package (server-side) | 100% client-side en navegador |
| **Estabilidad** | 5000 muestras simuladas | 100-1000 iteraciones con perturbación |

### 1.2 Filosofía Central

> **"No preguntamos cómo queda la red al final. Preguntamos cuánta energía total (activación) se ahorró del RESTO del sistema a lo largo del tiempo si apagamos este nodo."**

El sistema implementa una métrica de **derrame (spillover)**: el impacto de una intervención se mide por cuánto reduce la activación acumulada de los demás nodos, excluyendo el nodo intervenido.

## 3. ⚙️ Parámetros del Sistema

### 3.1 Parámetros Globales de NIRA

```javascript
var NIRA = {
    // ─── Parámetros del Motor Legacy ───
    MAX_TICKS:         600,      // Tope de ticks por simulación (legacy)
    THRESHOLD:         0.003,    // Umbral de estabilidad (Σ|Δvalue|)
    MIN_STABLE_TICKS:  3,        // Ticks consecutivos bajo umbral
    INTENSITY:         1,        // Intervención: +1 a la alta
    
    // ─── Clamp de valores (CRÍTICO) ───
    VALUE_MIN:         0,        // Límite inferior
    VALUE_MAX:         1,        // Límite superior
    IMPACT_SAFETY_FACTOR: 1.05,  // Margen de seguridad (5%)
    
    // ─── Motor Definitivo (AUC) ───
    HORIZON_MIN:       600,      // Ticks mínimos de simulación
    HORIZON_MAX:       2000,     // Ticks máximos de simulación
    HORIZON_FACTOR:    4,        // Multiplicador: diámetro × velocidad
    
    // ─── Ejecución ───
    CHUNK_TICKS:       500,      // Tamaño de rebanada asíncrona
    DEFAULT_ITERATIONS: 100      // Iteraciones por defecto
};
```

### 3.2 Tabla de parámetros y su significado clínico

| Parámetro | Valor | Significado Clínico |
|---|---|---|
| `VALUE_MIN/MAX` | `[0, 1]` | Rango normalizado de activación psicopatológica (0% a 100%) |
| `INTENSITY` | `+1` | Magnitud de la perturbación inicial (intervención clínica) |
| `HORIZON_FACTOR` | `4` | Tiempo suficiente para que la señal cruce la red y rebote en bucles |
| `perturbationStrength` | `0.05` | Ruido aleatorio ±5% para romper determinismo (variabilidad diaria del paciente) |
| `IMPACT_SAFETY_FACTOR` | `1.05` | Cota dura para aserciones: `N × 1 × 1.05` |

## 4. 📐 Ecuaciones y Métricas Fundamentales

### 4.1 Horizonte Dinámico

El tiempo de simulación se calcula dinámicamente según la topología de la red:

$$
\text{HORIZON} = \text{clamp}\big(\text{diameter} \times \text{signalSpeed} \times \text{HORIZON\_FACTOR},\; \text{HORIZON\_MIN},\; \text{HORIZON\_MAX}\big)
$$

Donde:
- **`diameter`**: Longitud del camino más largo entre cualquier par de nodos (calculado por BFS en `calculateDiameter`)
- **`signalSpeed`**: Velocidad de propagación de señales (configurable en Loopy, default = 3)
- **`HORIZON_FACTOR`**: Multiplicador empírico (4)

**Justificación**: Una red con diámetro 5 y velocidad 3 necesita al menos `5 × 3 × 4 = 60` ticks para que una señal cruce, rebote y se estabilice. Se clampa entre 600 y 2000 por seguridad.

### 4.2 Área Bajo la Curva (AUC) - Métrica Definitiva

El impacto de intervenir un nodo se define como:

$$
\text{Impacto}_i = \text{AUC}_{\text{control}} - \text{AUC}_{\text{intervención}_i}
$$

Donde:

$$
\text{AUC} = \sum_{t=0}^{\text{HORIZON}} \text{tickScore}(t)
$$

Y el **tickScore** en cada instante es:

$$
\text{tickScore}(t) = \sum_{\substack{n \in \text{nodos} \\ n \neq \text{nodo\_intervenido}}} \max(0,\; \text{value}_n(t))
$$

**Interpretación**: 
- **Impacto positivo alto** → Al apagar el nodo, el resto de la red se desactivó mucho más (diana terapéutica prioritaria)
- **Impacto negativo** → La intervención aumentó la activación global (freno protector, ¡no tocar!)
- **Impacto ≈ 0** → El nodo es periférico, su intervención no tiene efecto sistémico

### 4.3 Métrica de Derrame (Spillover) - Legacy

En el motor legacy (`NIRA.analyze`), el impacto se calcula como:

$$
\text{impact} = \text{totalScore}(\text{post},\; \text{exclude}=\text{diana}) - \text{totalScore}(\text{control},\; \text{exclude}=\text{diana})
$$

Que se expande a:

$$
\text{impact} = (\text{totalScore}_{\text{post}} - \text{value}_{\text{diana,post}}) - (\text{baseScore} - \text{value}_{\text{diana,control}})
$$

**Propósito**: Excluir el nodo intervenido elimina el confusor del "+1 propio" y aísla el efecto cascada sobre el resto del sistema.

### 4.4 Cota de Rango del Impacto

El impacto máximo teórico para una red de `N` nodos es:

$$
|\text{impacto}|_{\max} = N \times (\text{VALUE\_MAX} - \text{VALUE\_MIN}) \times \text{IMPACT\_SAFETY\_FACTOR}
$$

Para una red de 7 nodos: $7 \times 1 \times 1.05 = 7.35$

**Por qué no usar un número fijo**: En redes saturadas, el impacto escala con N. Un valor fijo (ej. 10) sería inconsistente.

### 4.5 Normalización del Impacto

Al finalizar el análisis legacy, los impactos se normalizan a [0, 1]:

$$
\text{impactNormalized}_i = \frac{\text{impact}_i}{\max_j |\text{impact}_j|}
$$

Con redes de seguridad para valores `NaN` o infinitos.

### 5.2 Paso a paso detallado de `_runSinglePass`

#### Paso 1: Cálculo del Horizonte Dinámico
```javascript
var diameter = NIRA.calculateDiameter(model);  // BFS
var HORIZON = Math.max(
    NIRA.HORIZON_MIN, 
    Math.min(NIRA.HORIZON_MAX, diameter * loopy.signalSpeed * NIRA.HORIZON_FACTOR)
);
```

El BFS explora desde cada nodo y encuentra el camino más largo:
```javascript
for (var start = 0; start < N; start++) {
    // BFS desde 'start'
    // maxDist = máxima distancia encontrada
}
```

#### Paso 2: Perturbación Aleatoria
```javascript
var perturbationStrength = 0.05;
for (var i = 0; i < nodes.length; i++) {
    var noise = (Math.random() - 0.5) * 2 * perturbationStrength;
    nodes[i].value = Math.max(0, Math.min(1, nodes[i].value + noise));
}
```

**Justificación teórica**: Rompe el determinismo. Si la red empieza siempre en el mismo estado, siempre daría el mismo ranking. El ruido simula la variabilidad diaria del paciente.

#### Paso 3: Función `simulateWithAUC(clampNode)`
```javascript
function simulateWithAUC(clampNode) {
    NIRA.restore(loopy, perturbedSnap);
    var auc = 0;
    
    for (var t = 0; t < HORIZON; t++) {
        // INTERVENCIÓN: Bloquear el nodo a 0 CADA TICK
        if (clampNode) {
            clampNode.value = 0;
            // Si es Molar, también sus hijos
            if (clampNode.isMolar && clampNode.children) {
                for (var c = 0; c < clampNode.children.length; c++) {
                    var child = model.getNode(clampNode.children[c]);
                    if (child) child.value = 0;
                }
            }
        }
        
        model.update();           // Física nativa de Loopy
        NIRA.clampValues(model);  // Mantener [0,1]
        
        // Forzar emisión de señales cada 10 ticks
        if (t % 10 === 0) {
            for (var i = 0; i < nodes.length; i++) {
                if (nodes[i].aggregate) {
                    clearTimeout(nodes[i].aggregate);
                    nodes[i].sendSignal({
                        delta: nodes[i].value * 0.3,
                        age: 1000000
                    });
                    nodes[i].deltaPool = 0;
                }
            }
        }
        
        // Medir score EXCLUYENDO el nodo intervenido
        var tickScore = 0;
        for (var i = 0; i < nodes.length; i++) {
            var n = nodes[i];
            if (clampNode && n.id === clampNode.id) continue;
            
            var nodeValue = n.value;
            // Si es Molar, incluir hijos ocultos
            if (n.isMolar && n.children && n.children.length > 0) {
                for (var c = 0; c < n.children.length; c++) {
                    var child = model.getNode(n.children[c]);
                    if (child && child.hidden) {
                        nodeValue += child.value;
                    }
                }
            }
            tickScore += Math.max(0, nodeValue);
        }
        auc += tickScore;
    }
    return auc;
}
```

#### Paso 4: Cálculo del Impacto
```javascript
var impact = baselineAUC - interventionAUC;
```

### 5.3 Sistema de Snapshot/Restore (Máquina del Tiempo)

#### `NIRA.snapshot(loopy)`
Captura el estado completo sin usar `serialize()` (que no preserva valores ni señales):

```javascript
var snap = {
    mode: loopy.mode,
    signalSpeed: loopy.signalSpeed,
    nodeValues: [],           // value de cada nodo
    nodeCount: model.nodes.length,
    edgeCount: model.edges.length,
    edgeSignals: []           // señales en vuelo por arista
};
```

#### `NIRA.restore(loopy, snap)`
Restaura el estado sin disparar `model/changed` (evita autosave):

```javascript
for(var i=0;i<n;i++){
    model.nodes[i].value = snap.nodeValues[i];
}
Edge.allSignals = [];
for(var i=0;i<e;i++){
    edge.signals = snap.edgeSignals[i].slice();
    for(var j=0;j<signals.length;j++){
        Edge.allSignals.push(signals[j]);
    }
}
publish("view/changed");  // Solo redibujar, no guardar
```

## 6. 🧠 Manejo Especial de Nodos Molares

Los nodos Molares (grupos clínicos tipo "Evitación Experimental" que contienen hijos como "Evitar fiestas", "No contestar llamadas") requieren tratamiento especial:

### 6.1 Intervención sobre un Molar
```javascript
if (clampNode.isMolar && clampNode.children) {
    for (var c = 0; c < clampNode.children.length; c++) {
        var child = model.getNode(clampNode.children[c]);
        if (child) child.value = 0;
    }
}
```

**Justificación**: Intervenir un constructo molar (ej. "Evitación") implica clínicamente intervenir todos sus componentes.

### 6.2 Medición del tickScore con Molares
```javascript
if (n.isMolar && n.children && n.children.length > 0) {
    for (var c = 0; c < n.children.length; c++) {
        var child = model.getNode(n.children[c]);
        if (child && child.hidden) {
            nodeValue += child.value;
        }
    }
}
```

**Justificación**: Los hijos ocultos contribuyen a la activación total del sistema aunque no sean visibles.

## 8. 📊 Análisis de Estabilidad: Interpretación del Informe

El informe final muestra tres métricas por nodo:

| Métrica | Definición | Interpretación Clínica |
|---|---|---|
| **Top 1** | % de simulaciones donde el nodo fue la MEJOR diana | Prioridad clínica principal |
| **Top 3** | % de simulaciones donde estuvo entre las 3 mejores | Robustez como diana |
| **Top 5** | % de simulaciones donde estuvo entre las 5 mejores | Relevancia sistémica |

### 8.1 Reglas de interpretación

- **Top 1 > 40%** (verde): Diana prioritaria. Intervenir aquí tiende a producir el mayor efecto sistémico.
- **Top 1 bajo + Top 3/5 alto**: Diana secundaria útil para abordajes multimodales.
- **Top 5 ≈ 0%**: Nodo periférico, poco efecto sistémico esperado.
- **Varios nodos con Top 1 similar (30-50%)**: Considerar abordaje simultáneo.
- **Top 1 > 70%**: La red está organizada alrededor de ese factor; abordar antes que síntomas secundarios.

## 9. 🆚 Comparación con NIRA Académico (Lunansky et al. 2022)

### 9.1 Diferencias conceptuales profundas

| Aspecto | NIRA Académico | NIRA-Loopy |
|---|---|---|
| **Modelo** | Ising (ferromagnético, binario) | Sistema dinámico continuo con retroalimentación |
| **Intervención** | Alterar threshold (probabilidad espontánea de activación) | Clamping a 0 en cada tick (bloqueo sostenido) |
| **Métrica** | Sum-score de 5000 observaciones simuladas | AUC temporal con horizonte dinámico |
| **Direccionalidad** | Alleviating vs. Aggravating | Solo Alleviating (bloqueo a 0) |
| **Bucles** | No captura (modelo estático) | Captura bucles de retroalimentación positiva/negativa |
| **Tiempo** | No tiene dimensión temporal | Horizonte dinámico basado en diámetro de red |
| **Validación** | Test de permutación, moderación, estabilidad | Estabilidad por Monte Carlo (100-1000 iteraciones) |

### 9.2 Ventajas de nuestra implementación

1. **Captura no-linealidades**: Los bucles de retroalimentación positiva (ej. Ansiedad ↔ Evitación) pueden generar explosiones exponenciales, controladas por el clamp `[0,1]`.

2. **Horizonte adaptativo**: Una red de 3 nodos no necesita 2000 ticks; una de 15 sí. El BFS ajusta el tiempo de simulación.

3. **Perturbación estocástica**: Rompe el determinismo y simula la variabilidad diaria del paciente.

4. **Métrica temporal (AUC)**: Captura no solo el estado final, sino **toda la trayectoria** de desactivación.

5. **Integración con clínica real**: Los nodos Molares, las aristas con signo (+/-), y la grilla MMEE de 3x3 son elementos clínicamente significativos.

### 9.3 Limitaciones respecto al NIRA académico

1. **Sin test de permutación**: No calculamos p-values estadísticos (aunque podríamos agregarlos).
2. **Sin test de moderación**: No verificamos si los pesos de las aristas cambian durante la intervención.
3. **Solo intervenciones alleviating**: No simulamos "aggravating" (empeorar un síntoma para ver qué nodos son preventivos).
4. **Sin validación empírica**: Como advierten Lunansky et al., los efectos proyectados requieren validación clínica real.

## 10. 🛡️ Robustez y Edge Cases

### 10.1 Protección contra explosión exponencial

```javascript
NIRA.clampValues = function(model){
    for(var i=0;i<nodes.length;i++){
        var v = nodes[i].value;
        if(v < NIRA.VALUE_MIN)      nodes[i].value = NIRA.VALUE_MIN;
        else if(v > NIRA.VALUE_MAX) nodes[i].value = NIRA.VALUE_MAX;
    }
};
```

**Por qué es crítico**: Sin esto, los bucles de retroalimentación positiva harían que `Σ values` explotara a cientos de miles, rompiendo las matemáticas.

### 10.2 Antirreentrada

```javascript
if (NIRA.running) return;  // No correr dos análisis a la vez
NIRA.running = true;
// ... al finalizar:
NIRA.running = false;
```

### 10.3 Integridad del modelo

```javascript
var _integrityOK = function(){
    return (model.nodes.length === snap.nodeCount) &&
           (model.edges.length === snap.edgeCount);
};
```

Si el usuario edita la red durante el análisis, se aborta con error.

### 10.4 Sincronización de señales asíncronas

El hack `if (t % 10 === 0)` fuerza la emisión de señales acumuladas en `deltaPool`, simulando síncronamente el `setTimeout` de 100ms de Loopy:

```javascript
if (t % 10 === 0) {
    for (var i = 0; i < nodes.length; i++) {
        if (nodes[i].aggregate) {
            clearTimeout(nodes[i].aggregate);
            nodes[i].aggregate = null;
            nodes[i].sendSignal({
                delta: nodes[i].value * 0.3,
                age: 1000000
            });
            nodes[i].deltaPool = 0;
        }
    }
}
```

## 11. 🚀 Caché y Optimización

### 11.1 Sistema de caché en `Loopy.js`

```javascript
self.niraCache = {
    hash: null,        // Hash del modelo (nodos + aristas)
    simulaciones: 0,   // Número de simulaciones cacheadas
    results: null      // Resultados del último análisis
};

self.getModelHash = function() {
    var nodes = model.nodes.map(n => ({id: n.id, label: n.label, init: n.init}))
                          .sort((a,b) => a.id - b.id);
    var edges = model.edges.map(e => ({from: e.from.id, to: e.to.id, signal: e.signal}))
                          .sort((a,b) => (a.from - b.from) || (a.to - b.to));
    return JSON.stringify({ nodes: nodes, edges: edges });
};
```

**Invalidación**: Cada vez que `publish("model/changed")` se dispara, `invalidateNiraCache()` limpia el caché.

### 11.2 Micro-batching para no congelar UI

```javascript
var batchSize = 5;  // 5 iteraciones por lote
var limit = Math.min(currentIter + batchSize, iterations);
for (var i = currentIter; i < limit; i++) {
    var singleRunResults = NIRA._runSinglePass(loopy);
    // Contar Top 1, 3, 5
}
setTimeout(processBatch, 0);  // Ceder el hilo al navegador
```

## 14. 📝 Resumen Ejecutivo

**NIRA-Loopy** es una implementación 100% client-side de análisis de intervención en redes psicopatológicas que:

1. **Usa un motor AUC con horizonte dinámico** (calculado por BFS) para medir el impacto temporal acumulado de intervenir cada nodo.

2. **Implementa una métrica de derrame (spillover)** que excluye el nodo intervenido, aislando el efecto cascada sobre el resto del sistema.

3. **Maneja nodos Molares** con lógica especial (intervención distribuida a hijos, medición inclusiva).

4. **Protege contra explosiones** mediante clamp `[0,1]` y sincronización de señales asíncronas.

5. **Reporta estabilidad** mediante Monte Carlo con perturbación estocástica, generando rankings Top 1/3/5 en porcentaje.

6. **Se diferencia del NIRA académico** por usar un sistema dinámico continuo (no Ising binario) y capturar bucles de retroalimentación.

**La interpretación clínica**: Los nodos con mayor Top 1 representan las **dianas terapéuticas prioritarias** — aquellos síntomas o procesos que, al ser intervenidos, producen la mayor reducción acumulada de activación en el resto del sistema psicopatológico del paciente.

### 🗂️ 1. ¿Qué otros archivos intervienen cuando ejecutas NIRA?

Aunque `NIRA.js` es el "cerebro" del análisis, no trabaja solo. Depende críticamente de la física y la estructura de Loopy. Estos son los archivos que interactúan directamente:

1. **`Model.js`**: NIRA llama constantemente a `model.update()` para avanzar la simulación tick a tick. También usa `model.nodes`, `model.edges` y `model.getNode()` para leer la topología.
2. **`Node.js`**: NIRA lee y modifica `node.value`, llama a `node.takeSignal()` para inyectar la intervención, y maneja `node.aggregate` y `node.deltaPool` para forzar la emisión de señales.
3. **`Edge.js` (o el objeto global `Edge`)**: NIRA monitorea `Edge.allSignals` para saber si quedan señales "en vuelo" (crucial para evitar falsas convergencias) y restaura las señales en cada `snapshot`.
4. **`Sidebar.js` / `PlayControls.js`** (o el archivo de UI que tenga el botón): Es el que escucha el clic del usuario, bloquea la interfaz, llama a `NIRA.analyzeStability()` y recibe el `finalRanking` para mostrarlo en la pantalla (o generar el PDF).
5. **`Loopy.js`**: NIRA cambia temporalmente `loopy.mode` a `MODE_PLAY` (porque en modo EDIT los nodos se resetean a su `init` en cada tick) y usa `publish("view/changed")` para que el canvas se redibuje si es necesario.

### 🧠 2. Explicación Pedagógica de `NIRA.js` (Tu Código Actual)

Tu archivo `NIRA.js` es una joya de ingeniería porque combina la física nativa de Loopy con una métrica avanzada (AUC) y manejo de estados. Vamos a dividirlo en **6 bloques funcionales**:

#### Bloque A: Los "Knobs" o Parámetros Globales (Líneas 1-45)
Aquí defines las reglas del juego.
*   **`MAX_TICKS: 600` / `THRESHOLD: 0.003`**: Son los parámetros del motor *legacy* (`runSimulationUntilStable`).
*   **`VALUE_MIN: 0`, `VALUE_MAX: 1`**: **CRÍTICO.** Es el "clamp" (sujeción). Sin esto, un bucle de retroalimentación positiva (ej: Evitación ↔ Vergüenza) haría que los valores crecieran al infinito (ej: 5000.4), rompiendo las matemáticas. Esto los mantiene en un rango clínico interpretable (0% a 100% de activación).
*   **`HORIZON_MIN: 600`, `HORIZON_MAX: 2000`, `HORIZON_FACTOR: 4`**: Son los parámetros del **Motor Definitivo (AUC)**. Dictan que la simulación correrá como mínimo 600 ticks, pero se ajustará dinámicamente según el tamaño de la red.

#### Bloque B: Topología y Métricas (Líneas 48-115)
*   **`getVisibleNodes`**: Filtra los nodos. Si un nodo es hijo de un Molar y está `hidden = true`, lo ignora para el ranking, pero...
*   **`calculateDiameter`**: Usa un algoritmo BFS (Breadth-First Search) para encontrar el camino más largo entre dos nodos. *¿Por qué?* Para calcular el `HORIZON` dinámico. Una red de 3 nodos no necesita 2000 ticks; una de 15 nodos con bucles largos, sí.
*   **`totalScore(model, excludeNode)`**: Esta es la magia del **"Efecto Derrame" (Spillover)**. Suma el valor de todos los nodos visibles, **EXCLUYENDO** el nodo que intervenimos (y sus hijos molares). *Filosofía:* No nos importa que el nodo intervenido baje a 0 (eso es obvio). Nos importa cuánto bajó **el resto del sistema** gracias a esa intervención.

#### Bloque C: La Máquina del Tiempo (Snapshot / Restore) (Líneas 118-165)
*   **`snapshot(loopy)`**: Toma una "foto" instantánea. No solo guarda el `value` de cada nodo, sino que guarda **todas las señales viajando por las aristas** (`edge.signals`). Esto es vital para que, al restaurar, no haya señales "fantasma" de una simulación anterior.
*   **`restore(loopy, snap)`**: Devuelve la red exactamente al estado de la foto, reconstruyendo `Edge.allSignals`. No dispara `model/changed` para no guardar automáticamente un estado intermedio en el servidor/localStorage.

#### Bloque D: El Motor de Simulación Legacy (Líneas 168-218)
*   **`runSimulationUntilStable`**: Es el motor antiguo. Corre `model.update()` hasta que el cambio total entre ticks sea menor al `THRESHOLD` (0.003) durante 3 ticks seguidos, **Y** no queden señales en vuelo (`Edge.allSignals.length === 0`).
*   *Detalle técnico:* El bloque `if(t % 10 === 0)` es un "hack" brillante. Fuerza a los nodos a emitir sus señales acumuladas (`deltaPool`) de forma síncrona, simulando el `setTimeout` de 100ms de Loopy, evitando que la simulación se quede "trabada" esperando timers asíncronos.

#### Bloque E: El Análisis Asíncrono Principal (`analyze`) (Líneas 221-380)
Este es el que se ejecuta si usas la función clásica de 1 sola pasada.
1.  Bloquea la UI para que el usuario no haga clic en otro lado.
2.  Toma un `snapshot` inicial.
3.  Corre la simulación de **Control** (sin tocar nada) para obtener el `baseScore`.
4.  En un bucle (`step` con `setTimeout` para no congelar el navegador), interviene cada nodo uno por uno:
    *   Restaura el snapshot.
    *   Llama a `_prepareIntervention` (inyecta `INTENSITY: 1` al nodo, o a sus hijos si es Molar).
    *   Corre la simulación hasta estabilizarse.
    *   Calcula el `impact` (diferencia de spillover).
5.  Al final, normaliza los impactos de 0 a 1, ordena de mayor a menor, y pinta las "auras" solo en el Top 5.

#### Bloque F: EL MOTOR DEFINITIVO (`_runSinglePass`) (Líneas 392-465)
**Este es el corazón de lo que construimos juntos.** Es el que usa `analyzeStability` para las 100/1000 iteraciones.
1.  **Horizonte Dinámico:** Calcula el diámetro y fija los `HORIZON` ticks (ej: 600 a 2000).
2.  **Perturbación:** Agrega un ruido aleatorio de ±0.05 a todos los nodos. *¿Por qué?* Para romper el determinismo. Si la red empieza siempre en 0, siempre da el mismo resultado. El ruido simula la variabilidad diaria del paciente.
3.  **Función `simulateWithAUC(clampNode)`**:
    *   Restaura al estado *perturbado*.
    *   Si hay un `clampNode` (el nodo que estamos "tratando"), lo fuerza a `value = 0` en **cada tick** (y a sus hijos molares).
    *   Corre un bucle `for` de `t = 0` a `HORIZON`.
    *   En cada tick: avanza la física (`model.update()`), aplica el clamp `[0,1]`, fuerza señales, y **suma el `tickScore`** (la activación del resto de la red) a la variable `auc`.
4.  **Cálculo del Impacto:** `impact = baselineAUC - interventionAUC`.
    *   Si el impacto es **positivo y alto**, significa que al "apagar" ese nodo, la suma total de activación del resto de la red a lo largo del tiempo fue mucho menor. **Ese es tu Top 1.**

#### Bloque G: Análisis de Estabilidad (`analyzeStability`) (Líneas 468-515)
*   Ejecuta `_runSinglePass` en lotes de 5 (`batchSize = 5`) usando `setTimeout`. Esto permite que el navegador "respire" y actualice la barra de progreso sin congelarse.
*   En cada iteración, mira el resultado de `_runSinglePass` y suma +1 al contador `top1`, `top3` o `top5` del nodo ganador.
*   Al llegar a las `iterations` (ej: 1000), convierte esos conteos en porcentajes y te entrega el ranking final.

### 💡 Resumen Clínico de lo que hace este código

Cuando aprietas el botón, este archivo le dice al navegador:
> *"Toma la red actual, agrégale un poco de ruido realista. Luego, mide cuánta 'energía patológica' (AUC) circula por el sistema durante un tiempo calculado matemáticamente (Horizonte). Después, repite ese proceso 1000 veces, pero cada vez 'apagando' clínicamente un nodo diferente (y sus hijos molares). El nodo cuyo apagado genere la mayor caída en la energía total del **resto** del sistema, es tu diana terapéutica principal."
